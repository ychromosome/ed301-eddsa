# Arithmetic implementation register

This register records deliberately local arithmetic code whose rationale can
become stale as compilers and libraries change. Revisit every entry whenever
the canonical Fedora Rust toolchain changes.

| Area | Current implementation | Why it exists | Permanent evidence |
| --- | --- | --- | --- |
| Runtime field borrow | Safe `u64::borrowing_sub` chain | Replaces the larger Hacker's-Delight expansion. Rust 1.97.1 and 1.98.0 produced two reviewed branchless SBB/CMOV profiles; older `overflowing_sub` code had produced a secret-dependent branch. | Full core differential/KAT tests, four core taint cases, EVP-provider taint, and `scripts/check-final-provider-codegen.sh` on each OpenSSL-lane module. |
| Compile-time field borrow | Local Hacker's-Delight identity | `u64::borrowing_sub` is not const-stable. This path constructs public immutable tables and is not executed on secrets at runtime. | Table reconstruction and field differential tests. |
| Field wide reduction | Positive `high * (2^99 - 947)` MAC fold | Exploits the fixed pseudo-Mersenne modulus while removing borrow-heavy work. | Montgomery differential oracle, reachable one-hot/boundary/random cases, taint and final codegen gate. |
| Scalar wide reduction | Natural 304+304 split and fixed `2^304 mod L` | Reuses constant-time `crypto-bigint` Montgomery operations and removes the ten-word Horner loop. | Independently reproduced radix, block-boundary/all-one-hot/random division-oracle tests, taint and final codegen gate. |
| Field helper inlining | `#[inline(always)]` on the five-limb product, square, small-product and reduction helpers (`multiply_wide`, `square_wide`, `reduce_wide` and their pieces), matching the X301 crate | The helpers took ten-limb arrays by value through real calls; on Rust 1.98.0 the reduction alone was half of the verification profile. Inlining removes the call and copy overhead (measured: verify 102 to 96 µs, key import 115 to 108 µs, sign 32 to 31 µs on a Ryzen 5950X) without changing any arithmetic. | The final codegen gate accepts each helper either as a branch-free local symbol or as inlined-and-never-called; the inlined bodies are then covered by the branch-free checks of `double`, `add`, `add_affine` and `is_valid`. Differential/KAT tests unchanged. |
| Lazy reduction inside the group formulas | Private `Fe301Lazy` (`[0, 2p)`) and `Fe301LazyLinear` (`[0, 4p)`) types, as in the X301 ladder; `double`, `add` and `add_affine` keep products lazily reduced and sums or differences unreduced, tighten a value once where a difference needs a subtrahend below `2p`, and canonicalise only the four returned coordinates. The canonical `Fe301` remains the sole representation outside one formula; tables, encoding, decoding, validity and the compile-time formulas are unchanged. | Every canonical add or sub cost a full borrow chain plus conditional correction and every product a conditional subtraction; with those removed a doubling drops from about 330 to 270 ns and a mixed addition likewise (measured on a Ryzen 5950X, on top of the inlined helpers: verify 96 to 86 µs, key import 108 to 97 µs, sign 31 to 28.5 µs, keygen 30 to 28 µs; against the pre-inlining baseline 102/115/32/31 µs). Bounds: operands below `4p < 2^303` give wide products below `2^606`, for which the two-fold reduction is shown to return a value below `2p` (see `reduce_wide_unreduced`); a small product of a value below `2p` by a 32-bit constant folds once to below `2p`. | Field differential test `lazy_arithmetic_matches_the_montgomery_oracle_and_bounds` (extreme operands `2p - 1` and `4p - 2`, 10,000 random operands through every lazy operation, explicit bound assertions against `2p` and `4p`); the existing ladder, fixed-base, Straus and reference-vector tests cover the formulas; taint and final codegen gates on the new lowering. |
| Bounded dependency arithmetic | Source-bound `crypto-bigint 0.7.5` fork with four `wrapping_add`, two `wrapping_neg` and four fixed-schedule `wrapping_sub` sites | Cargo profiles are not transitive. Explicit wrapping semantics remove secret-dependent arithmetic guards and unreachable fixed-schedule underflow guards without requiring a downstream package override. | Upstream checksum and exact patch register, external consumer with overflow checks on, four Valgrind taint cases and final provider codegen gate. |

The final codegen gate is intentionally compiler-specific. Passing it under one
compiler is not a promise about another compiler, architecture, build profile,
or future inlining decision.
